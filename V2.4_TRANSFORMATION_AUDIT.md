# Denzel Tinashe Portfolio — V2.4 Proof-First Transformation

## Goal

V2.4 applies the production audit directly to the portfolio. The objective is not “more Apple styling.” It is to make the site prove product design + engineering ability faster, reduce buyer/recruiter inference, and remove release-quality issues that contradicted the craft positioning.

## Release blockers fixed

- Fixed the CTA color/specificity failure that made the black header and hero buttons render with black text on black backgrounds.
- Reworked keyboard focus to use `currentColor`, so focus indicators remain visible on both light and dark controls.
- Reduced the hero type scale and preserved intentional desktop line breaks to prevent orphaned words at wide desktop sizes.
- Changed the canonical origin to `https://www.denzeltinashe.com`, matching the current production redirect direction.

## Proof and credibility changes

- Replaced invented hero metrics with architecture/product evidence.
- BeforeUScroll now uses real product screens hosted by the live project.
- Spotly is presented as a verified five-surface platform and session architecture rather than a fictional dashboard.
- GoCreate Insights uses documented dataset counts and a source/reconciliation model.
- MealRecap is explicitly shown as a product architecture flow; it does not imply fictional traction data.
- Added live-product links for MealRecap and BeforeUScroll.
- Rebuilt all four case studies around role, status, timeline, product problem, challenge, decisions, explicit tradeoff, evidence, systems, and outcome/proof.

## Website portfolio changes

- The website section no longer gives eight identical tiles equal visual weight.
- FPC Wichita, St. Mark Cathedral COGIC, and POM Church are featured as richer deployed-web stories.
- Oil City Church, Calvary Apostolic Church, KDYM, HACIA, and Aftershock remain in a compact shipped-work archive with live/source links.
- This keeps the breadth without positioning Denzel primarily as a church-site specialist.

## Hiring path changes

- Added a dedicated Experience section using the existing public résumé information.
- Added visible Résumé, LinkedIn, and GitHub paths.
- Added concise professional chronology for Wichita State / GoCreate, KDYM, FPC Wichita, Aftershock + HACIA, and PosCloud.
- Added a clearer About section focused on how Denzel works, not only brand language.

## Client conversion changes

- Replaced mailto-only primary conversion with a dedicated `/start` flow.
- The inquiry form captures project type, stage, timeline, budget range, and desired outcome.
- `/api/inquiry` supports Resend when `RESEND_API_KEY` is configured.
- The form has an explicit pre-filled email fallback when server delivery is unavailable.
- Added honeypot, minimum-fill-time, payload-size, origin, and required-field validation.

## Technical changes

- Homepage is now a Server Component instead of hydrating the entire page.
- Client JavaScript is limited to the responsive/shrinking navigation, reveal behavior, and inquiry form.
- Removed the legacy V1 homepage CSS from the global stylesheet; portal/gallery styling remains scoped in their own modules.
- Added `robots.txt`, `sitemap.xml`, and `manifest.webmanifest` through Next.js metadata routes.
- Added Person JSON-LD on the homepage and CreativeWork JSON-LD on case studies.
- Added dedicated 1200x630 Open Graph assets for the homepage and four case studies.
- Added global security headers: `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `X-Frame-Options`, and `Cross-Origin-Opener-Policy`.
- Preserved the existing noindex/noarchive behavior for client routes and Gabby gallery infrastructure.

## Intentionally not fabricated

V2.4 does not invent:

- testimonials;
- client quotes;
- revenue or user counts;
- conversion lifts;
- App Store status;
- team size;
- fake product screenshots.

When a verified quantitative outcome is unavailable, the case study states a technical/product outcome that is directly supported by the implementation.

## Deployment configuration

For direct project-form delivery, configure:

- `RESEND_API_KEY`
- `PROJECT_INQUIRY_FROM` — verified sender recommended
- `PROJECT_INQUIRY_TO` — defaults to `denzelnyatsanza@gmail.com`

Without those variables, the form surfaces a pre-filled email fallback instead of pretending the message was delivered.

## Final QA gate

Run after dependency installation:

```bash
npm ci
npm run build
npm run dev
```

Then verify:

- desktop hero at 1440, 1728, and 2048 widths;
- mobile at 390 and 430 widths;
- header CTA text visibility;
- keyboard focus on light and dark surfaces;
- all four case studies;
- `/start` form with and without Resend configured;
- `/robots.txt`, `/sitemap.xml`, and `/manifest.webmanifest`;
- client portal/login routes;
- `/gabby` and client download behavior;
- reduced-motion mode;
- Lighthouse / Core Web Vitals.
